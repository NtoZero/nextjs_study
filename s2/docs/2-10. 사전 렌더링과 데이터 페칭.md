### **1. React에서의 데이터 페칭**

### **1.1 데이터 페칭 과정**

1. **불러온 데이터를 보관할 State 생성**
2. **데이터 페칭 함수 생성**
3. **컴포넌트 마운트 시점에 데이터 페칭 함수 호출**
4. **데이터 로딩 중일 때의 예외 처리**

```tsx
tsx
복사편집
export default function Page() {
  const [state, setState] = useState(); // 1. 데이터를 보관할 State 생성

  const fetchData = async () => {
    const response = await fetch("..."); // 2. 데이터 페칭 함수 생성
    const data = await response.json();
    setState(data);
  };

  useEffect(() => {
    fetchData(); // 3. 컴포넌트 마운트 시점에 fetchData 호출
  }, []);

  if (!state) return "Loading..."; // 4. 데이터 로딩 중일 때의 예외 처리

  return <div>데이터 표시</div>;
}

```

### **1.2 단점**

- **초기 접속 시 요청부터 데이터 로딩까지 시간이 오래 걸림**
    - 이유: 데이터 요청이 **컴포넌트 마운트 시점**에서 발생하기 때문

### **2. Next.js에서의 데이터 페칭**

### **2.1 사전 렌더링의 장점**

1. **사전 렌더링으로 초기 렌더링 속도(FCP)가 빨라짐**
2. **렌더링 이전에 서버로부터 데이터를 미리 호출 가능**
3. **데이터가 페칭된 상태로 페이지를 클라이언트에 전달**

### **2.2 React와 Next.js 데이터 페칭 비교**

| **구분** | **React App** | **Next.js App** |
| --- | --- | --- |
| **데이터 요청 시점** | 컴포넌트 마운트 이후 발생 | 사전 렌더링 중 발생 (마운트 이후에도 가능) |
| **장단점** | 데이터 요청이 늦어져 초기 렌더링이 느려질 수 있음 | 데이터 요청 시점이 빨라 초기 렌더링 속도가 개선됨 |

### **2.3 의문 및 답변**

- **Q1. 사전 렌더링이 오래 걸릴 수 있지 않은가?**
    - A: 네, 데이터 응답이 크거나 서버 상태가 좋지 않다면 사전 렌더링 시간이 오래 걸릴 수 있습니다.
- **Q2. React의 로딩 바 형식이 더 나은 선택 아닌가?**
    - A: 사전 렌더링이 오래 걸릴 경우, Next.js는 **빌드 타임(Build Time)**에 데이터를 미리 페칭하도록 설정할 수 있습니다. Next.js는 다양한 사전 렌더링 옵션을 제공합니다.

### **3. Next.js의 다양한 사전 렌더링 방식**

1. **서버사이드 렌더링 (SSR)**
    - 요청이 들어올 때마다 서버에서 사전 렌더링 진행
    - 페이지마다 동적인 데이터를 필요로 할 때 적합
2. **정적 사이트 생성 (SSG)**
    - 빌드 타임에 페이지를 사전 렌더링
    - 데이터가 자주 변경되지 않는 페이지에 적합
3. **증분 정적 재생성 (ISR)**
    - 정적 페이지를 유지하면서 주기적으로 데이터를 갱신
    - 데이터 변경 주기가 일정한 페이지에 적합
