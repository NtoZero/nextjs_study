# Next 오류 발생 로그

## 1. searchParams 및 params 동적으로 가져오는 것에서 문제 발생

### 1.1. 코드 참조 `app/(with-searchbar)/search > page.tsx`

- searchParams 또는 params 를 동적으로 가져와 API 호출 하게 되면 에러 발생 [1.1] 참조
```javascript
import BookItem from "@/components/book-item";
import { BookData } from "@/types";

export default async function Page({
  searchParams,
}: {
  searchParams: {
    q?: string;
  };
}) {
  const response = await fetch(
    `${process.env.NEXT_PUBLIC_API_HOST}/book/search?q=${searchParams.q}`
  );
  if (!response.ok) {
    return <div>오류가 발생했습니다...</div>;
  }

  const books: BookData[] = await response.json();

  return (
    <div>
      {books.map((book) => (
        <BookItem key={book.id} {...book} />
      ))}
    </div>
  );
}

```

### 1.2. 오류 로그 참조

- 오류 로그:
```html
page.tsx:12  Server   Error: Route "/search" used `searchParams.q`. `searchParams` 
should be awaited before using its properties. 
Learn more: https://nextjs.org/docs/messages/sync-dynamic-apis
    at Page (page.tsx:12:11)
    at JSON.parse (<anonymous>)
```
- 참조 공식 홈페이지 : [Dynamic APIs are Asynchronous](https://nextjs.org/docs/messages/sync-dynamic-apis)
- 관련 stackoverflow 문서 : [Route "/[locale]" used `params.locale`. `params` should be awaited before using its properties](https://stackoverflow.com/questions/79143162/route-locale-used-params-locale-params-should-be-awaited-before-using)

### 1.3. 문제 원인

Next.js 14 이후 searchParams와 같은 동적 API들은 동기적이지 않을 수 있음.
즉, 서버 컴포넌트에서 searchParams를 직접 사용할 경우 비동기적으로 다뤄야 할 수도 있음.
```javascript
export default async function Page({
  searchParams,
}: {
  searchParams: {
    q?: string;
  };
}) {
  const response = await fetch(
    `${process.env.NEXT_PUBLIC_API_SERVER_URL}/book/search?q=${searchParams.q}`
  );
}
```
- 위 코드에서 searchParams.q를 즉시 사용하면, Next.js 내부에서 searchParams가 아직 준비되지 않았을 수도 있음.
  이로 인해 **"searchParams should be awaited"**라는 오류가 발생하는 것.

### 1.4. 해결 방법
공식 문서에서 제시한 방식대로 useSearchParams()를 클라이언트 컴포넌트에서 사용하거나,
서버 컴포넌트에서 안전한 방식으로 searchParams를 처리해야 함.

- 방법 1: useSearchParams()를 활용하여 클라이언트 컴포넌트에서 처리 (권장)
  Next.js 14에서는 useSearchParams()를 사용하면 자동으로 비동기적인 처리 문제를 해결할 수 있음.
  즉, searchParams.q가 서버에서 비동기적으로 불러와질 가능성이 있다면, 클라이언트에서 useSearchParams()를 사용하도록 리팩토링하면 됨.
- 수정 코드 (클라이언트 컴포넌트에서 useSearchParams 사용)
  1️⃣ SearchBooks.tsx (클라이언트 컴포넌트로 변경)
```javascript
"use client"; // 클라이언트 컴포넌트로 설정

import { useSearchParams } from "next/navigation";
import BookItem from "@/components/book-item";
import { BookData } from "@/types";
import { useEffect, useState } from "react";

export default function SearchBooks() {
  const searchParams = useSearchParams();
  const q = searchParams.get("q") || "";

  const [books, setBooks] = useState<BookData[]>([]);
  const [error, setError] = useState(false);

  useEffect(() => {
    if (!q) return;

    fetch(`${process.env.NEXT_PUBLIC_API_SERVER_URL}/book/search?q=${q}`)
      .then((res) => {
        if (!res.ok) throw new Error("API 요청 실패");
        return res.json();
      })
      .then(setBooks)
      .catch(() => setError(true));
  }, [q]);

  if (error) return <div>오류가 발생했습니다...</div>;

  return (
    <div>
      {books.map((book) => (
        <BookItem key={book.id} {...book} />
      ))}
    </div>
  );
}
```
2️⃣ page.tsx (서버 컴포넌트)
```javascript
export default function Page() {
  return <SearchBooks />;
}
```

- 방법 2: 서버 컴포넌트에서 searchParams를 안전하게 비동기 처리
- Next.js 14에서는 searchParams가 비동기적으로 제공될 수 있기 때문에, 아래와 같이 처리하는 것이 안전함. 
- 📌 수정 코드 (서버 컴포넌트에서 안전하게 searchParams 사용)
```javascript
import BookItem from "@/components/book-item";
import { BookData } from "@/types";

export default async function Page({
                                     searchParams,
                                   }: {
  searchParams: {
    q?: string;
  };
}) {
  // `searchParams`가 동기적으로 제공되지 않을 수도 있으므로 안전하게 처리
  const params = await Promise.resolve(searchParams);
  const q = params.q || "";

  const response = await fetch(
    `${process.env.NEXT_PUBLIC_API_SERVER_URL}/book/search?q=${q}`
  );

  if (!response.ok) {
    return <div>오류가 발생했습니다...</div>;
  }

  const books: BookData[] = await response.json();

  return (
    <div>
      {books.map((book) => (
        <BookItem key={book.id} {...book} />
      ))}
    </div>
  );
}

```
### 최적의 해결책
1️⃣ SEO가 중요하고, 초기 렌더링에서 데이터가 필요하다면:
👉 방법 2 (서버 컴포넌트에서 Promise.resolve(searchParams) 처리)
→ 서버에서 데이터를 가져와 렌더링하므로 SSR 친화적.

2️⃣ 사용자가 페이지 내에서 동적으로 검색어를 변경할 가능성이 크다면:
👉 방법 1 (useSearchParams(), 클라이언트 컴포넌트)
→ 검색어가 바뀌어도 클라이언트에서 즉시 반영 가능.

📢 Next.js 공식 문서를 따른다면, 클라이언트 컴포넌트 (useSearchParams) 방식이 가장 최신 방식이므로 추천! 🚀


### best-Practice
1. You should await params, like:
  `export async function POST(request: Request, { params }: { params: Promise<{ unit_id: string }> }) {`
2. and then
  `const { unit_id: unitId } = await params`
3. 코드 적용 사례
```javascript
import style from "./page.module.css";

export default async function Page({
  params,
}: {
  // ✅ Promise 객체의 제네릭으로 id 감싸기
  params: Promise<{ id: string | string[] }>;
}) {
  // ✅ params를 await하여 안전하게 처리
  const { id } = await params;

  const response = await fetch(
    `${process.env.NEXT_PUBLIC_API_HOST}/book/${id}`
  );

  if (!response.ok) {
    return <div>오류가 발생하였습니다.</div>;
  }

  const book = await response.json();

  const { title, subTitle, description, author, publisher, coverImgUrl } = book;

  return (
    <div className={style.container}>
      <div
        className={style.cover_img_container}
        style={{ backgroundImage: `url('${coverImgUrl}')` }}
      >
        <img src={coverImgUrl} alt={title} />
      </div>
      <div className={style.title}>{title}</div>
      <div className={style.subTitle}>{subTitle}</div>
      <div className={style.author}>
        {author} | {publisher}
      </div>
      <div className={style.description}>{description}</div>
    </div>
  );
}
```
